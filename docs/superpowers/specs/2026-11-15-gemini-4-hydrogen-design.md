# Short Design: Upgrade Nong ChokChuay Default LLM to `gemini-4-hydrogen` & Natural Thai Kindergarten Persona

Date: 2026-11-15
Status: Approved

## 1. Intent & Why
เจ้าของโปรเจกต์ต้องการ:
1. เปลี่ยนโมเดลสมองของ **"น้องโชคช่วย" (Nong ChokChuay)** จาก `gemini-2.5-flash` เป็น **`gemini-4-hydrogen`**
2. ปรับปรุง **System Prompt** และการประมวลผลคำตอบของบอทใหม่ เพราะของเดิมพูดจาแข็งทื่อเหมือนบอทคอลเซ็นเตอร์ ให้กลายเป็นผู้ช่วยครูรุ่นน้องคู่ใจประจำห้องอนุบาลไทยที่คุยเป็นธรรมชาติ อบอุ่น เข้าใจบริบทงานครูปฐมวัยไทย และช่วยทั้งงานเอกสารและงานร่างข้อความสื่อสารผู้ปกครองได้จริง

## 2. Goals, Non-Goals, and Constraints
- **Goals:**
  - เปลี่ยนค่าเริ่มต้น `LLM_MODEL` ของทั้งระบบเป็น `gemini-4-hydrogen` ครบทุกจุด (`config.py`, `line_service.py`, `extractor.py`, `worker.js`, `wrangler.toml`, `.env.example`, `docs/STATUS.md`, ชุดทดสอบ และ `.env` ในเครื่อง)
  - รองรับพฤติกรรมโหมดคิดวิเคราะห์ (`thinking: true`) ของ `gemini-4-hydrogen` โดยไม่ทำให้คำตอบถูกตัดขาดจาก `MAX_TOKENS` หรือติด `thought` part
  - ปรับ `build_nong_chok_system_instruction()` ให้ใช้โครงสร้างบุคลิก **"ผู้ช่วยครูอนุบาลไทยรุ่นน้องคู่ใจ"** แบบ Dual-Mode Grounding:
    - **โหมดข้อมูลระบบ (ยอดเบิกจ่าย / เอกสาร / เด็กแพ้อาหาร):** ยึดจาก `CONTEXT` 100% ห้ามแต่งตัวเลขหรือชื่อเด็กเอง และช่วยเชื่อมโยงความเสี่ยงแพ้อาหารให้ชัดเจน
    - **โหมดคู่คิดครูอนุบาล (ชวนคุย / ให้กำลังใจ / ร่างข้อความแจ้งผู้ปกครองใน LINE / คิดกิจกรรม-นิทาน-เพลงเด็ก 3–6 ขวบ):** ช่วยคิดและเกลาภาษาอย่างเป็นธรรมชาติโดยไม่ถูกจำกัดอยู่แค่ตารางฐานข้อมูล
  - ยกเลิกการบังคับขึ้นต้น `"สวัสดีครับครูพิ้งกี้!"` ซ้ำทุกข้อความ (ลบ post-processing ที่แปะคำทักทายทับหน้าออก) และปรับ `temperature` ฝั่งแชทจาก `0.35` เป็น `0.65` (คงฝั่งสกัด JSON ที่ `0.1`)
- **Non-Goals & Anti-Goals:**
  - ไม่เปลี่ยนสถาปัตยกรรมตาม `docs/adr/0001` และ `docs/adr/0002` (ห้ามส่งไฟล์ภาพ/PDF ดิบออกนอกเครื่อง ส่งเฉพาะข้อความ OCR เท่านั้น และยังคง fallback กลับเป็น Offline Thai Regex เสมอเมื่อ LLM ล้มเหลว)
  - ไม่กระทบงานการ์ดมาสคอตที่ค้างอยู่ใน working tree หลักของเจ้าของโปรเจกต์
- **Constraints:**
  - `gemini-4-hydrogen` ใช้ `thoughtsTokenCount` ประมาณ 300–950 tokens ต่อคำขอ ต้องตั้ง `maxOutputTokens` เป็น `2048` (แชท) และ `4096` (สกัด JSON) พร้อม `timeout=20` วินาที
  - ห้ามปล่อยให้ศัพท์เทคนิค (`CONTEXT`, `OCR`, `Database`, `JSON`) หลุดไปในข้อความตอบครูบน LINE

## 3. Approaches Considered
1. **เปลี่ยนค่าเริ่มต้นเป็น `gemini-4-hydrogen` ทั้งระบบ + ปรับ Thinking Params + ยกเครื่อง System Prompt แบบ Dual-Mode (เลือกใช้วิธีนี้):**
   - ขยาย `maxOutputTokens` เป็น `2048`/`4096`, `timeout=20`, กรองข้าม `thought` part, ใช้ `temperature=0.65` ในแชท, เอาโค้ดแปะคำทักทายแข็งๆ ออก และใช้ System Prompt ที่อิงงานจริงของครูปฐมวัยไทย
2. **เปลี่ยนเฉพาะชื่อโมเดลโดยไม่แก้พารามิเตอร์หรือ Prompt (ไม่เลือก):**
   - ติดเพดาน `maxOutputTokens: 450` ทันที และน้ำเสียงยังคงแข็งทื่อเหมือนเดิม
3. **แยกตัวแปร `CHAT_LLM_MODEL` และ `EXTRACT_LLM_MODEL` คนละตัว (ไม่เลือก):**
   - เพิ่มความซับซ้อนในการตั้งค่าเกินความจำเป็น เพราะ `gemini-4-hydrogen` สกัด JSON ได้รวดเร็ว (~3.7 วินาที) อยู่แล้ว

## 4. Builder Scope
- อัปเดตโค้ด ค่าตั้งต้น เอกสาร และชุดทดสอบในสาขา `codex/gemini-4-hydrogen` (แตกจาก `origin/main`)
- ซิงก์การแก้ไขเดียวกันและ `LLM_MODEL=gemini-4-hydrogen` ลงในเครื่องหลักโดยรักษางานค้างใน working tree ไว้ครบถ้วน และรีสตาร์ตเซิร์ฟเวอร์พอร์ต `8765` เพื่อตรวจการทำงานจริงในเครื่อง
- เปิด PR และรอผล GitHub Actions CI ก่อนขออนุมัติ merge/deploy ตาม `AGENTS.md` หมวดที่ 6
